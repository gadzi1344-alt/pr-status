# Pear — статус сервиса

Отдельная страница для Vercel: проверяет HTTP-ответ `https://peargram.online` серверной функцией. Доступность сайта — не то же самое, что проверка всех функций или ресурсов VPS. История, uptime и графики не подделываются.

## Публикация
1. Загрузите содержимое папки в репозиторий GitHub (файлы должны быть в корне).
2. В Vercel нажмите Add New → Project, импортируйте репозиторий и нажмите Deploy. Настройки сборки не требуются.
3. При желании в Project → Settings → Domains подключите `status.peargram.online` и выполните указания Vercel по DNS. DNS записей заранее не угадывайте.
4. Для отдельной проверки приложения добавьте в Environment Variables переменную `STATUS_URL` — публичный HTTPS URL вашего health endpoint, например `https://peargram.online/health` (только если он реально существует). Создайте новый deployment, чтобы применить переменную.

Откройте опубликованную страницу: она проверяет сайт при загрузке, по кнопке и раз в 60 секунд, пока вкладка активна. Время ответа измеряется от Vercel, а не от посетителя. HTTP 200–399 считается доступностью, 400–599 — ошибкой; при таймауте 8 секунд показывается отсутствие ответа. Редиректы не отслеживаются, поэтому их конечная цель не проверяется. Страница остаётся недоступной, если сам Vercel недоступен.

## Локальный запуск
Нужен Node.js 20+ и Vercel CLI: `npx vercel dev`. Простое открытие HTML не запускает серверную функцию. 

## Для расширения мониторинга
Можно добавить закрытый сбор CPU, RAM, диска, нагрузки и состояния сервисов. Потребуется безопасный источник данных (например, отдельный агент/экспортер с ограниченным доступом или существующий мониторинг). Не публикуйте IP, порты, токены, пароли и административные панели на публичной странице. Секреты храните в серверных переменных окружения, а не в HTML. Не отправляйте пароли или приватные ключи в чат.
